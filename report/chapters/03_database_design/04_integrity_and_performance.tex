\section{Integrity and Query Performance}

\subsection{Integrity Enforcement}

Data consistency is enforced at two levels:
\begin{itemize}
    \item \textbf{Database level}: primary keys, foreign keys, enum domains, and unique constraints.
    \item \textbf{Application level}: permission checks in \code{includes/project-functions.php}, \code{includes/member-functions.php}, and \code{includes/task-functions.php} before insert/update/delete operations.
\end{itemize}

This dual-layer approach protects against both accidental UI misuse and direct API misuse.

\subsection{Performance Considerations}

The schema includes indexes tailored to frequent operations:
\begin{itemize}
    \item Project access: \code{idx\_owner}, \code{idx\_project\_code}.
    \item Membership and requests: \code{idx\_project}, \code{idx\_user}, and status composite indexes.
    \item Task filtering: \code{idx\_status}, \code{idx\_priority}, \code{idx\_due\_date}, \code{idx\_assigned}.
\end{itemize}

Search and filtering logic uses prepared statements and condition composition in
\code{includes/task-functions.php} (notably \code{searchProjectTasks}), reducing SQL injection risk and keeping query plans index-friendly.
